\textbf{Abstract:}
Network intrusion detection is a critical component of modern cybersecurity infrastructure.
As network attacks become increasingly sophisticated and voluminous, traditional signature-based
detection systems struggle to keep pace.
This project presents a machine-learning-based Network Intrusion Detection System (NIDS)
built on the CICIDS2017 benchmark dataset, which comprises approximately 2.83 million
network flow records covering both benign traffic and 14 distinct attack types.
A comprehensive data preparation pipeline was developed, including duplicate removal,
infinite-value handling, label standardisation (grouping 15 raw labels into 8~categories),
and data-driven feature selection using both statistical tests (Kruskal--Wallis) and
model-based importance (Random Forest).
XGBoost achieved the highest F1-macro of 0.8585.
The final model was deployed as an interactive Streamlit dashboard for real-time classification.
Overall, the project demonstrates that a well-engineered data pipeline combined with
ensemble tree-based classifiers can achieve robust multi-class intrusion detection performance.

%1. INTRODUCTION
\newpage
\section{Introduction}

The rapid proliferation of devices connected to the Internet and the exponential growth of network traffic have made cybersecurity one of the most pressing challenges of the digital era.
According to recent industry reports, the frequency and sophistication of cyberattacks continue to escalate, with network intrusions causing billions of dollars in annual losses \cite{cybersecurityventures}.
As a result, Network Intrusion Detection Systems (NIDS) have become an indispensable layer of defense in organizational security architectures.

Traditional NIDS rely on signature-based methods, where pre-defined patterns of known attacks are matched against incoming traffic.
While effective for detecting well-known threats, these approaches inherently fail to identify novel or zero-day attacks, as they depend on a continuously updated signature database \cite{zeroday_ml_review}.
This limitation has motivated the research community to explore machine learning (ML) approaches, which can learn complex traffic patterns directly from data and generalise to previously unseen attack variants \cite{ml_ids_survey}.

The CICIDS2017 dataset, published by the Canadian Institute for Cybersecurity, has emerged as one of the most widely used benchmark datasets for evaluating ML-based NIDS.
It contains approximately 2.83~million labelled network flow records, generated in a controlled environment that simulates realistic modern-day network traffic and a diverse set of attack scenarios including Denial-of-Service (DoS/DDoS), port scanning, brute force attacks, web-based exploits, botnet activity, and the Heartbleed vulnerability \cite{cicids2017}.
Each flow is characterised by 78~network-level features extracted using the CICFlowMeter tool, covering metrics such as packet lengths, inter-arrival times, flow durations, and TCP flag counts.

This project tackles the multi-class network intrusion detection problem on the CICIDS2017 dataset:
given a set of network flow features as \textbf{input}, the system must produce a classification label (\textbf{output}) indicating whether the traffic is benign or belongs to one of seven attack categories.
The specific objectives are:

\begin{enumerate}[label=(\roman*)]
    \item Design and implement a data preprocessing and feature engineering pipeline that handles the dataset's inherent quality issues (missing values, infinite values, duplicate records, and redundant features).
    \item Conduct exploratory data analysis (EDA) to understand the dataset's statistical properties, class distribution, and inter-feature relationships.
    \item Train, tune, and compare multiple ML classifiers (Logistic Regression, Decision Tree, Random Forest, XGBoost, LightGBM, and Extra Trees) with appropriate handling of class imbalance.
    \item Deploy the best-performing model as an interactive web-based dashboard for demonstration purposes.
\end{enumerate}

The motivation for choosing this topic is threefold.
First, network security directly impacts every organization and individual connected to the internet, making it a topic of significant real-world importance.
Second, the CICIDS2017 dataset provides a realistic and well-labeled benchmark that enables reproducible research \cite{cicids2017}.
Third, the multi-class nature of the problem (rather than simple binary anomaly detection) introduces challenging class-imbalance issues that require careful data engineering and modelling strategies, offering a rich learning opportunity for applied machine learning.


%2. RELATED WORKS
\newpage
\section{Related Works}

This section reviews recent published works that employ machine learning techniques for network intrusion detection, with a particular focus on studies that utilize the CICIDS2017 dataset or similar flow-based datasets.
\subsection*{Interpretable Machine Learning Framework for Anomaly Detection in Intrusion Detection Systems using XAI Techniques}
Building a lightweight framework using Decision Tree (DT) and Random Forest (RF) models integrated with Explainable AI (XAI) techniques, specifically SHAP and LIME in order to enhance transparency in cybersecurity. These tools are used to provide global feature importance and local decision reasoning, helping security analysts understand why specific network traffic is flagged as an anomaly. For the dataset and data preprocessing, the authors utilized the NSL-KDD dataset, an improved version of KDD’99 that addresses redundancy and class imbalance. Preprocessing included one-hot encoding for categorical attributes, min-max normalization for numeric features, and data cleaning to remove duplicate records. Regarding the results, the Random Forest model achieved the highest performance with an accuracy of approximately 98.1\%, a precision of 96.4\%, and an AUC-ROC of 0.99. The Decision Tree model also performed competitively at 96.2\% accuracy \cite{Interpretable_ML_for_IDS_Anomaly_Detection}. The XAI analysis identified key features such as service type, source/destination counts (srv\_count), and time-to-live (sttl) as major influencers in detection decisions. However, the paper identifies several limitations, primarily involving ethical and security trade-offs. There is a risk that XAI could lead to privacy leaks of sensitive user metadata or be abused by adversaries who might use the provided explanations to sidestep detection mechanisms. Additionally, the study notes that models may still be susceptible to bias if training data overrepresents specific network behaviors. 


\subsection*{A Learning Approach for The Identification of Network Intrusions Based on Ensemble XGBoost Classifier}
The paper proposes a robust framework to enhance the detection of cyber threats in network traffic,. The main approach of this study is centered on the XGBoost ensemble learner, chosen for its speed and accuracy in parallel tree boosting,. To optimize the model, the authors employed an ensemble feature selection method using XGBoost’s feature importance scores to reduce the original 78 attributes down to 34 relevant features, thereby decreasing model complexity and training time,. Furthermore, the One Versus Rest (OVR) technique was used to convert the multi-class dataset into a binary classification problem to distinguish between benign and malicious activities. For the dataset and data preprocessing, the researchers utilized the CICIDS2017 dataset, which is favored for containing modern, representative attack types such as DoS, Botnet, and DDoS,. The preprocessing phase included Exploratory Data Analysis (EDA) to understand the data properties, followed by feature encoding to convert categorical variables into numerical formats,. Additionally, min-max scaling was applied to normalize the features into a interval, ensuring the learning classifier could process the data effectively. The results obtained from the experimentation across eight different data captures were highly successful, achieving an average accuracy of 98\%,. Other performance metrics were equally strong, with precision, recall, and F1-score all reaching 0.98, and an AUC-ROC score of 0.99 \cite{NID_ensemble_XGBoost}. Despite these high performance figures, some limitations can be noted. While the study emphasizes building an "interpretable model" through feature importance, it does not incorporate advanced Explainable AI (XAI) tools like SHAP or LIME for detailed local decision reasoning. Additionally, the use of the OVR technique simplifies the detection into a binary "benign vs. malicious" classification, which might limit the system's ability to provide granular identification of specific attack categories in a single-model output. 


\subsection*{Evaluating machine learning-based intrusion detection systems with explainable AI: enhancing transparency and interpretability}
The core idea is to combine multiple Machine Learning (ML) models—such as XGBoost, CatBoost, Random Forest, and Multilayer Perceptron (MLP)—with Explainable AI (XAI) methods, including SHAP, LIME, and ELI5, to generate both global and local interpretations of detection outcomes. In terms of data handling, the research employs the UNSW-NB15 dataset, which includes more than 2.5 million instances across nine attack categories. The preprocessing pipeline is thorough, consisting of duplicate removal, feature selection using Recursive Feature Elimination (RFE), normalization through Min-Max scaling, and class balancing with SMOTE. The experimental findings show that XGBoost and CatBoost deliver the best performance, each reaching an accuracy of 87\% while maintaining a low false positive rate of 0.07. Importantly, the XAI techniques highlight Source-to-Destination Time-to-Live (sttl) and Destination Service Count (ct\_srv\_dst) as the most influential features in identifying malicious traffic. Despite these promising results, the study acknowledges several limitations, including increased computational overhead from XAI integration, dependence on a single dataset (UNSW-NB15), and the possibility of false negatives, which may result in undetected advanced attacks \cite{ML_based_NIDS_XAI}.

\subsection*{RADAR: A TTP-based Extensible, Explainable, and Effective System for Network Traffic Analysis and Malware Detection}
RADAR’s core idea is to leverage the MITRE ATT\&CK framework to identify attacker behaviors (TTPs) directly from network traffic. It adopts a modular “divide-and-conquer” design, where each TTP is analyzed using a separate Decision Tree classifier \cite{radar}. This model choice enhances explainability, as analysts can trace the exact logical rules and network features behind each prediction. The system then applies aggregation strategies (P1, P2, or P3) to determine whether an overall sample should be classified as malicious. For evaluation, RADAR is tested on a large-scale real-world dataset containing more than 2.28 million samples and around 85 million network flows, collected from sources such as Ember, MalRec, MalShare, and VirusShare. During preprocessing, raw PCAP data is transformed into NetFlow records using YAF (Yet Another Flowmeter), ensuring a lightweight and payload-independent pipeline. These flows are stored in a Neo4j database, where feature-based and heuristic rules are applied to identify specific TTPs. The results show that RADAR achieves strong performance, with an AUC of 0.868, comparable to modern black-box models. It also maintains a false positive rate below 0.2 while delivering high detection accuracy, clearly outperforming traditional rule-based systems. However, the study notes several limitations. Some TTPs—such as the use of uncommon ports—are common in both benign and malicious traffic, meaning TTP detection alone is not sufficient without machine learning support. Additionally, variations in TTP distributions across datasets require environment-specific tuning. Lastly, although the framework is extensible, it currently supports only a limited set of TTPs tailored to NetFlow-based analysis. 

\medskip
\noindent
In summary, while existing studies demonstrate strong classification performance on the CICIDS2017 dataset, several common limitations persist: many works do not adequately address the severe class imbalance present in the dataset, some apply feature scaling or resampling before the train-test split (introducing data leakage), and few provide a deployable end-to-end system.
This project addresses these gaps by implementing a carefully ordered preprocessing pipeline that avoids data leakage, using robust statistical methods for feature selection, and deploying the final model through an interactive Streamlit dashboard.

\section{Data Preparation}

\subsection{Dataset Overview}

The CICIDS2017 (Canadian Institute for Cybersecurity Intrusion Detection System 2017) dataset is one of the most comprehensive and widely-cited benchmark datasets for network intrusion detection research.
It was generated by the Canadian Institute for Cybersecurity at the University of New Brunswick and is publicly available on Kaggle and the CIC website.
The dataset captures five days of network activity (Monday to Friday), where Monday contains only benign traffics and the subsequent days include various simulated attacks injected into realistic background traffic.

The raw data is distributed across \textbf{8~CSV files}, one per day and attack scenario.
When concatenated, the combined dataset comprises \textbf{2,830,743~rows} and \textbf{79~columns} (78~features + 1~label column), totalling approximately 1.7\,GB in memory.

\subsection{Data Cleaning Pipeline}

A systematic preprocessing pipeline was designed and implemented to address several data quality issues inherent in the raw dataset.
The pipeline is executed sequentially to ensure each step builds on a clean foundation.

\subsubsection{Column Name Standardisation}
Leading and trailing whitespace characters were stripped from all column names using \texttt{str.strip()}.
This step is necessary because the dataset introduces inconsistent spacing in column headers, which can lead to silent errors when accessing columns programmatically.

\subsubsection{Duplicate Removal}
The dataset was found to contain \textbf{308,381~duplicate rows} (10.89\% of total records).
These duplicates arise because identical network flows can appear across overlapping capture windows.
All duplicate rows were removed while retaining the first occurrence, reducing the dataset from 2,830,743 to \textbf{2,520,762~rows}.

\subsubsection{Identical Column Detection and Removal}

\subsection{Data-Driven Feature Selection}

Beyond removing identical columns during cleaning, a data-driven feature selection process was conducted to further reduce dimensionality and remove uninformative features.

\subsubsection{Correlation Analysis}
A Pearson correlation matrix was computed across all remaining numeric features.
Feature pairs with extremely high correlation ($|r| \geq 0.95$) were identified, and one feature from each pair was removed to mitigate multicollinearity.
The following \textbf{5~features} were dropped based on this criterion:

\begin{itemize}[nosep]
    \item \texttt{Total Backward Packets} (redundant with forward packet counts)
    \item \texttt{Total Length of Bwd Packets} (highly correlated with other length metrics)
    \item \texttt{Subflow Bwd Bytes} (identical information to backward byte counts)
    \item \texttt{Avg Fwd Segment Size} (equivalent to \texttt{Fwd Packet Length Mean})
    \item \texttt{Avg Bwd Segment Size} (equivalent to \texttt{Bwd Packet Length Mean})
\end{itemize}

\subsubsection{Statistical and Model-Based Feature Importance}

Prior to feature ranking, Levene's test was applied to assess variance homogeneity across attack-type groups for each feature.
Results confirmed that nearly all features exhibit significantly unequal variances ($p \leq 0.05$), validating the use of non-parametric methods rather than classical ANOVA.

Two complementary approaches were then used to evaluate feature importance:

\begin{enumerate}
    \item \textbf{Kruskal--Wallis H-test} (non-parametric): Since the data does not follow a Gaussian distribution and contains many outliers, the non-parametric Kruskal--Wallis test was chosen over ANOVA.
    This test evaluates whether the distributions of a feature differ significantly across the attack-type classes.
    Features with very low H-statistics indicate poor discriminative power.

    \item \textbf{Random Forest feature importance}: A Random Forest classifier (100~trees, max depth 20) was trained and its Gini-based feature importances were extracted.
    This model-based approach captures non-linear relationships that statistical tests may miss.
    The Random Forest achieved a cross-validation score of approximately 0.99, confirming its reliability for importance ranking.
\end{enumerate}

By combining results from both methods, \textbf{8~features} with consistently low importance scores were removed:

\begin{itemize}[nosep]
    \item \texttt{ECE Flag Count}, \texttt{RST Flag Count}, \texttt{Fwd URG Flags}, \texttt{Idle Std},
    \item \texttt{Fwd PSH Flags}, \texttt{Active Std}, \texttt{Down/Up Ratio}, \texttt{URG Flag Count}
\end{itemize}

\subsection{Experimental Setup}

\subsubsection{Data Splitting}
The cleaned dataset (2,520,762~samples, 52~numerical features) was split into training (80\%) and test (20\%) sets using stratified sampling with a fixed random seed (42) for reproducibility.
Stratification ensures that minority classes (e.g., Heartbleed with 11~samples) are proportionally represented in both sets.

\subsubsection{Evaluation Metrics}
Given the severe class imbalance, relying solely on accuracy would be misleading---a model predicting only BENIGN would achieve 83\% accuracy.
The following metrics are employed:

\begin{itemize}[nosep]
    \item \textbf{Accuracy:} The fraction of correctly classified samples:
    \begin{equation}
        \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
    \end{equation}

    \item \textbf{Precision (per class $c$):} The fraction of predicted positives that are truly positive:
    \begin{equation}
        \text{Precision}_c = \frac{TP_c}{TP_c + FP_c}
    \end{equation}

    \item \textbf{Recall (per class $c$):} The fraction of actual positives that are correctly identified:
    \begin{equation}
        \text{Recall}_c = \frac{TP_c}{TP_c + FN_c}
    \end{equation}

    \item \textbf{F1-score:} The harmonic mean of precision and recall:
    \begin{equation}
        F1_c = 2 \cdot \frac{\text{Precision}_c \cdot \text{Recall}_c}{\text{Precision}_c + \text{Recall}_c}
    \end{equation}

    \item \textbf{F1-macro:} The unweighted average of per-class F1 scores, treating all classes equally regardless of size:
    \begin{equation}
        F1_{\text{macro}} = \frac{1}{C} \sum_{c=1}^{C} F1_c
    \end{equation}
    This is the \textbf{primary metric} for model selection, as it is sensitive to minority class performance.

    \item \textbf{F1-weighted:} Weighted by class support, reflecting overall performance:
    \begin{equation}
        F1_{\text{weighted}} = \sum_{c=1}^{C} \frac{n_c}{N} \cdot F1_c
    \end{equation}

    \item \textbf{ROC-AUC (macro):} Area Under the Receiver Operating Characteristic Curve, averaged across classes using One-vs-Rest binarisation.

    \item \textbf{Matthews Correlation Coefficient (MCC):} A balanced measure that accounts for all four confusion matrix categories, ranging from $-1$ to $+1$:
    \begin{equation}
        \text{MCC} = \frac{TP \cdot TN - FP \cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}
    \end{equation}
\end{itemize}


\subsection{Baseline Models}

Six machine learning algorithms were trained as baseline models.
Each is described below with its core mechanism.

\subsubsection{Logistic Regression}
Logistic Regression is a linear classifier that models the probability of class membership using the sigmoid function.
For multi-class problems, the softmax (multinomial) extension is used:
\begin{equation}
    P(y = c \mid \mathbf{x}) = \frac{e^{\mathbf{w}_c^T \mathbf{x} + b_c}}{\sum_{j=1}^{C} e^{\mathbf{w}_j^T \mathbf{x} + b_j}}
\end{equation}
where $\mathbf{w}_c$ and $b_c$ are the weight vector and bias for class $c$.
The model is optimised using the L-BFGS solver with a maximum of 1,000 iterations.
StandardScaler was applied to normalise features before training, as linear models are sensitive to feature scales.

\subsubsection{Decision Tree}
A Decision Tree recursively partitions the feature space by selecting the split that maximises \textit{information gain}, measured using the Gini impurity:
\begin{equation}
    G(t) = 1 - \sum_{c=1}^{C} p_c^2
\end{equation}
where $p_c$ is the proportion of samples belonging to class $c$ in node $t$.
The tree was constrained with \texttt{max\_depth}$=20$ to prevent overfitting.

\subsubsection{Random Forest}
Random Forest is an ensemble of $B$ decision trees trained on bootstrap samples (bagging), with random feature subsets at each split.
The final prediction is determined by majority vote:
\begin{equation}
    \hat{y} = \text{mode}\{h_1(\mathbf{x}), h_2(\mathbf{x}), \dots, h_B(\mathbf{x})\}
\end{equation}
where $h_b(\mathbf{x})$ is the prediction of the $b$-th tree.
This procedure reduces variance compared to a single tree.
The model was configured with $B = 300$ trees.

\subsubsection{XGBoost (Extreme Gradient Boosting)}
XGBoost builds an additive ensemble of trees sequentially, where each new tree fits the residual errors of the previous ensemble.
The objective function at iteration $t$ is:
\begin{equation}
    \mathcal{L}^{(t)} = \sum_{i=1}^{N} l(y_i, \hat{y}_i^{(t-1)} + f_t(\mathbf{x}_i)) + \Omega(f_t)
\end{equation}
where $l$ is the loss function, $f_t$ is the new tree, and $\Omega(f_t) = \gamma T + \frac{1}{2}\lambda \|\mathbf{w}\|^2$ is the regularisation term (with $T$ being the number of leaves and $\mathbf{w}$ the leaf weights).
The loss is approximated using second-order Taylor expansion:
\begin{equation}
    \mathcal{L}^{(t)} \approx \sum_{i=1}^{N} \left[ g_i f_t(\mathbf{x}_i) + \frac{1}{2} h_i f_t^2(\mathbf{x}_i) \right] + \Omega(f_t)
\end{equation}
where $g_i = \partial l / \partial \hat{y}_i^{(t-1)}$ and $h_i = \partial^2 l / \partial (\hat{y}_i^{(t-1)})^2$ are the first and second-order gradients.
Class imbalance was addressed using computed sample weights based on inverse class frequency.

\subsubsection{LightGBM}
LightGBM is a gradient boosting framework that introduces two key optimisations:
\begin{itemize}[nosep]
    \item \textbf{Gradient-based One-Side Sampling (GOSS):} Retains all instances with large gradients and randomly samples from small-gradient instances, reducing computation while maintaining accuracy.
    \item \textbf{Exclusive Feature Bundling (EFB):} Bundles mutually exclusive features to reduce the effective number of features.
\end{itemize}
LightGBM uses \textit{leaf-wise} tree growth (growing the leaf with the maximum loss reduction) rather than level-wise, producing deeper and more specialised trees.
This makes it significantly faster than traditional gradient boosting, achieving a training time of 69.56s compared to XGBoost's 112.8s.

\subsubsection{Extra Trees (Extremely Randomized Trees)}
Extra Trees extends Random Forest by introducing additional randomness: instead of finding the optimal split threshold, it selects thresholds \textit{randomly} for each candidate feature.
This further reduces variance at the cost of slightly higher bias, and results in faster training (81.00s vs.\ Random Forest's 277.64s).

\subsection{Ensemble Model}

To explore whether combining multiple models could improve robustness, a \textbf{Soft Voting Classifier} was constructed using the three best baseline models: XGBoost, LightGBM, and Random Forest.

Soft Voting works by averaging the predicted probability distributions from each base model $m$:
\begin{equation}
    \hat{P}(y = c \mid \mathbf{x}) = \frac{1}{M} \sum_{m=1}^{M} P_m(y = c \mid \mathbf{x})
\end{equation}
The final prediction is the class with the highest average probability:
\begin{equation}
    \hat{y} = \arg\max_c \; \hat{P}(y = c \mid \mathbf{x})
\end{equation}
This approach is more nuanced than hard voting (majority rule) because it leverages the confidence levels of each model.

\subsection{Hyperparameter Tuning Results}

Unexpectedly, hyperparameter tuning \textit{degraded} performance for XGBoost and LightGBM, while Random Forest remained approximately unchanged.
This counter-intuitive result is attributed to three factors:

\begin{enumerate}
    \item \textbf{Extreme minority class noise in cross-validation:} The stratified subsample contained only 2~Heartbleed and 4~SQL Injection samples.
    With 3-fold CV, individual folds could contain 0 or 1 samples from these classes, causing the F1-macro optimisation target to become highly unstable.

    \item \textbf{Over-aggressive class rebalancing:} When \texttt{class\_weight='balanced'} is applied to extremely rare classes (e.g., Heartbleed with 2~samples in the subsample), the model assigns disproportionately large weights to these samples.
    LightGBM's tuned version collapsed to F1-macro of 0.097, with accuracy dropping to 68\% due to massive over-prediction of minority classes.

    \item \textbf{Suboptimal parameter combinations:} XGBoost's best-found parameters included \texttt{learning\_rate}$=0.01$ with only \texttt{n\_estimators}$=100$, which is an underfitting configuration requiring $\geq$1,000 estimators to converge.
\end{enumerate}

\noindent
\textbf{Key Takeaway:} When dealing with extreme class imbalance (classes with $<$20 samples), aggressive rebalancing techniques can do more harm than good.
The baseline models, which used moderate or no rebalancing, achieved better performance.

\subsection{Error Analysis}

Detailed error analysis was performed on the best-performing model (XGBoost baseline) to identify systematic misclassification patterns.

Figure~\ref{fig:top_misclassifications} highlights the most common misclassification pairs made by the selected XGBoost model.

\begin{figure}[H]
\centering
\includegraphics[width=\textwidth]{5.5.png}
\caption{Top Misclassification Pairs bar chart.}
\label{fig:top_misclassifications}
\end{figure}

\begin{enumerate}
    \item \textbf{Web Attack cross-confusion:} The most striking pattern is the mutual confusion between Web Attack -- XSS and Web Attack -- Brute Force.
    62.3\% of XSS attacks are misclassified as Brute Force, and 22.1\% of Brute Force are misclassified as XSS.
    This occurs because both attack types target web applications and share similar network-level features (HTTP traffic patterns, request rates, packet sizes).
    Distinguishing between them would likely require application-layer features (e.g., payload content) that are not present in the CICIDS2017 feature set.

    \item \textbf{BENIGN false positives:} A small number of benign samples are misclassified as PortScan (198), Bot (186), and DoS (78).
    In absolute terms these numbers appear significant, but relative to the 419,012~benign test samples, they represent a false positive rate of only 0.11\% --- approximately 1 false alert per 900 benign connections, which is generally acceptable in production IDS deployments.

    \item \textbf{Low total errors:} For XGBoost, the total number of misclassifications across all classes is approximately 700 out of 504,153~test samples, yielding an overall error rate of 0.13\%.
    The errors are concentrated in the extremely rare attack types where training data is insufficient.
\end{enumerate}


\subsection{Model Selection}

\subsubsection{Selection Criteria}
The final model was selected based on a multi-criteria ranking across four key metrics: F1-macro, F1-weighted, ROC-AUC (macro), and MCC.
Each model was ranked 1 (best) to 6 (worst) for each metric, and the average rank determined the final ordering.

XGBoost and LightGBM were tied in average rank (1.50).
\textbf{XGBoost was selected} as the final deployment model for the following reasons:

\begin{enumerate}
    \item \textbf{Higher F1-macro (0.859 vs.\ 0.830):} XGBoost is better at detecting minority attack classes, which is the primary objective of an intrusion detection system.
    Missing an attack (false negative) is more dangerous than a false alarm (false positive).

    \item \textbf{Perfect ROC-AUC (1.0):} XGBoost demonstrates perfect class separation in probability space, meaning that with appropriate threshold tuning, detection rates can be further optimised for specific deployment scenarios.

    \item \textbf{Reasonable training time (112.8s):} While not the fastest model, XGBoost's training time is practical for periodic retraining in production environments.
\end{enumerate}

\subsubsection{Why Not the Ensemble Model?}
Although the Voting Ensemble achieved marginally higher metrics than XGBoost alone, it was not selected for deployment due to practical considerations:

\begin{itemize}[nosep]
    \item \textbf{Model complexity:} The ensemble contains three separate models, resulting in a significantly larger model file and higher memory requirements.
    \item \textbf{Inference latency:} In network intrusion detection, real-time prediction speed is critical.
    The ensemble requires running all three models and averaging their outputs, tripling inference time.
    \item \textbf{Marginal improvement:} The performance gain does not justify the increased complexity and operational cost.
    In production IDS deployments, the trade-off favours the simpler, faster single model.
\end{itemize}

The trained XGBoost model was serialised and saved at \texttt{models/xgboost\_best\_model.joblib} for deployment.

\newpage
\section{Conclusion and Perspectives}

This project comprehensively addressed the multi-class network intrusion detection problem on the CICIDS2017 dataset through a rigorous end-to-end machine learning pipeline.
The key findings are:

\begin{enumerate}
    \item \textbf{Non-linear models are essential:} Logistic Regression's significantly lower performance (F1-macro: 0.567) compared to tree-based models ($>$0.78) confirms that network intrusion patterns require non-linear decision boundaries that cannot be captured by linear classifiers.

    \item \textbf{Gradient boosting outperforms bagging:} XGBoost (0.859) and LightGBM (0.830) outperform Random Forest (0.827) and Extra Trees (0.813) in F1-macro, demonstrating that sequential error correction is more effective than parallel averaging for this imbalanced dataset.

    \item \textbf{Aggressive class rebalancing can backfire:} Hyperparameter tuning with \texttt{class\_weight='balanced'} degraded all three tuned models, with LightGBM collapsing to F1-macro~0.097.
    Extreme minority classes (Heartbleed: 9~training samples, SQL Injection: 17~training samples) make balanced weighting unstable.

    \item \textbf{Data limitation is the primary bottleneck:} The remaining performance gap (particularly on Web Attack classes, F1 $\approx$0.3) cannot be solved by model selection or tuning alone.
    Improving detection of these rare attacks would require either more labelled samples or additional engineered features capturing application-layer behaviour.

    \item \textbf{Selected model:} XGBoost (baseline) achieves the best balance of minority class detection (F1-macro: 0.859), overall accuracy (99.87\%), and practical deployability.
\end{enumerate}

\noindent
\textbf{Limitations} of this work include: (i) the CICIDS2017 dataset, while comprehensive, was generated in a controlled lab environment and may not fully represent real-world network diversity; (ii) the feature set is limited to network-flow-level statistics and does not include payload or application-layer information; (iii) extremely rare attack classes (Heartbleed, SQL Injection) have insufficient samples for reliable evaluation.

\noindent
\textbf{Future perspectives:} If given more time and computational resources, several directions could be explored:
\begin{itemize}[nosep]
    \item Augmenting the dataset with additional IDS benchmarks (e.g., UNSW-NB15, CIC-IDS-2018) to improve minority class representation.
    \item Implementing online/incremental learning to adapt to evolving attack patterns in real-time.
    \item Enhancing the SHAP-based explainability module to provide actionable security insights for network administrators.
\end{itemize}
